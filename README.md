# DocVault — คลังเอกสารส่วนตัว

เว็บแอปสำหรับเก็บเอกสาร/รูปภาพสำคัญส่วนตัว พร้อมระบบล็อกอิน สแกน+ตั้งชื่อไฟล์อัตโนมัติ
ค้นหา ดาวน์โหลด และจัดหมวดหมู่

## ฟีเจอร์

1. **ระบบล็อกอิน** — สมัครสมาชิก/เข้าสู่ระบบด้วยอีเมล-รหัสผ่าน (เข้ารหัสด้วย bcrypt, session
   เป็น JWT เก็บใน httpOnly cookie) แต่ละบัญชีเห็นเฉพาะเอกสารของตัวเอง
2. **สแกน/อัปโหลดแล้วตั้งชื่อให้อัตโนมัติ** — อัปโหลดรูปถ่าย/สแกนเอกสาร (JPG, PNG, WEBP,
   HEIC) หรือไฟล์ PDF ระบบจะพยายามอ่านข้อความในเอกสาร (OCR สำหรับรูปภาพ ผ่าน tesseract.js,
   อ่านข้อความจริงสำหรับ PDF) แล้วตั้งชื่อไฟล์ให้อัตโนมัติจากข้อความที่พบ ถ้าไม่พบข้อความที่
   ใช้ได้ ระบบจะตั้งชื่อสำรองแบบ "เอกสารสแกน-วันที่" ให้แทน — และสามารถแก้ไขชื่อได้ทุกเมื่อ
   ในภายหลัง
3. **ดาวน์โหลดได้** — ดาวน์โหลดไฟล์ต้นฉบับกลับมาได้ทุกเมื่อ พร้อมดูตัวอย่างในเบราว์เซอร์
4. **ค้นหาได้** — ค้นหาจากชื่อเอกสาร ชื่อไฟล์เดิม หรือข้อความที่สแกนได้จากในเอกสาร
5. **จัดหมวดหมู่ได้** — สร้าง/ลบหมวดหมู่เอง กำหนดสีให้แต่ละหมวด และย้ายเอกสารระหว่างหมวดหมู่
   ได้อิสระ

## เทคโนโลยีที่ใช้

- Next.js (App Router) + TypeScript + Tailwind CSS
- Prisma ORM + SQLite (ไฟล์ฐานข้อมูลเดียว ไม่ต้องตั้งเซิร์ฟเวอร์ฐานข้อมูลแยก)
- Auth: JWT (jose) + bcryptjs — ไม่ได้ใช้บริการ third-party ใดๆ ข้อมูลทั้งหมดอยู่บนเซิร์ฟเวอร์ของคุณเอง
- OCR: tesseract.js (รันแยกเป็น child process ต่างหากเพื่อไม่ให้กระทบเซิร์ฟเวอร์หลักหากเกิด
  ปัญหา) และ pdf-parse สำหรับอ่านข้อความจาก PDF
- ไฟล์เอกสารถูกเก็บไว้ในโฟลเดอร์ `storage/uploads/<userId>/` บนดิสก์ (ไม่ได้อยู่ใต้ `public/`
  จึงต้องผ่าน API ที่มีการตรวจสอบสิทธิ์ก่อนถึงจะเข้าถึงไฟล์ได้)

## เริ่มต้นใช้งาน (Development)

```bash
npm install

# คัดลอกไฟล์ค่าคอนฟิกตัวอย่าง แล้วแก้ JWT_SECRET เป็นข้อความสุ่มยาวๆ ของคุณเอง
cp .env.example .env

# สร้างฐานข้อมูล SQLite ตาม schema
npx prisma migrate deploy

npm run dev
```

จากนั้นเปิด http://localhost:3000

## Build สำหรับ production

```bash
npm run build
npm run start
```

ก่อน deploy จริง ให้ตั้งค่า environment variable ต่อไปนี้:

- `DATABASE_URL` — path ของไฟล์ SQLite เช่น `file:./dev.db` (สัมพัทธ์กับโฟลเดอร์ `prisma/`)
- `JWT_SECRET` — ข้อความลับสุ่มความยาวอย่างน้อย 32 ตัวอักษร ใช้เซ็น session cookie ห้ามใช้ค่า
  ตัวอย่างในโปรดักชัน

โฟลเดอร์ `storage/uploads/` ต้องเขียนไฟล์ได้ (persist ข้ามการ deploy ถ้ารันบนเซิร์ฟเวอร์ที่มี
disk ถาวร เช่น VPS — หากใช้แพลตฟอร์ม serverless ที่ดิสก์ไม่ถาวร ควรแก้ `src/lib/storage.ts`
ให้เก็บไฟล์กับ object storage เช่น S3 แทน)

## หมายเหตุเรื่อง OCR

ฟีเจอร์ตั้งชื่ออัตโนมัติจากการสแกนรูปภาพต้องดาวน์โหลดไฟล์ข้อมูลภาษา (Thai + English) จาก CDN
สาธารณะในการใช้งานครั้งแรกที่มีการอัปโหลดรูปภาพ (ไฟล์ PDF ไม่ต้องใช้ขั้นตอนนี้เพราะอ่านข้อความ
ได้โดยตรง) จึงต้องมีการเชื่อมต่ออินเทอร์เน็ตขาออกจากเซิร์ฟเวอร์ หากเซิร์ฟเวอร์ไม่มีอินเทอร์เน็ต
หรือดาวน์โหลดไม่สำเร็จ ระบบจะไม่ค้าง/ไม่ล่ม แต่จะตกไปใช้ชื่อสำรองแบบ "เอกสารสแกน-วันที่" แทน
โดยอัตโนมัติ แล้วผู้ใช้สามารถแก้ไขชื่อเองภายหลังได้
